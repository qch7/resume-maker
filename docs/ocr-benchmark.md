# 本地 OCR 开销评测

2026-09-21，Windows 11 家庭版、Intel Core i9-12900HX、CPU 推理，2 个计算线程和 1 个算子间线程。使用合成证书，不包含真实个人资料。

## 选择和复现

默认使用 RapidOCR 1.4.4 + PP-OCRv4 移动模型。检测、识别及方向分类 ONNX 权重共约 15.44 MiB；这不含 Python、ONNX Runtime、OpenCV 等运行库。无需 GPU，识别时无需联网。暂不引入更重的服务端模型或生成式 OCR；本次没有测量它们，不能宣称轻量模型优于它们。

```powershell
uv run python scripts/benchmark_ocr.py
# 可选：--font <本机中文字体路径>
```

每种模式在独立进程运行，使用同一微软雅黑字体、1600×2260 像素输入。测试清晰正文、24 像素小字、14 像素极小字、倾斜 2 度并模糊的扫描页，以及倒置页。每页检查姓名、项目、奖项、日期、电话、编号和邮箱共 7 个固定字段。字段匹配只归一化空格，置信度不计作准确率。耗时为单次运行，含每页预处理，不含样本绘制；冷启动单列。峰值 RSS 每 20 毫秒采样，包含 Python、模型及图片，属于整进程实测值。

## 结果

| 模式 | 冷启动 | 五页总耗时 | 峰值 RSS | 字段命中 |
| --- | ---: | ---: | ---: | ---: |
| 固定 960，无复核 | 0.624 s | 4.176 s | 302.4 MiB | 28/35 |
| 默认 960，难页复核 2000 | 0.632 s | 6.447 s | 515.8 MiB | 35/35 |
| 固定 2000 | 0.645 s | 9.207 s | 697.3 MiB | 35/35 |

| 页面 | 固定 960 | 默认按需复核 | 固定 2000 |
| --- | ---: | ---: | ---: |
| 清晰 | 1.253 s，7/7 | 1.258 s，7/7 | 2.516 s，7/7 |
| 小字 | 0.816 s，7/7 | 0.813 s，7/7 | 1.631 s，7/7 |
| 极小字 | 0.223 s，0/7 | 2.469 s，7/7 | 1.540 s，7/7 |
| 轻微倾斜扫描 | 0.924 s，7/7 | 0.932 s，7/7 | 1.700 s，7/7 |
| 倒置 | 0.960 s，7/7 | 0.975 s，7/7 | 1.820 s，7/7 |

只有极小字页面触发默认模式的复核。默认模式在这一组合上比全程高分辨率少用约 30% 时间；极小字页因为先试一次再复核，耗时反而更高。OCR 内存会随图片面积、文字数量、运行库缓存和重试变化，不能按模型文件大小估算内存。

## 适用范围

五张同字体合成样本不足以代表真实准确率，未覆盖手写、复杂花纹、90 度旋转、反光、重压缩、罕见字和所有版面。35/35 是本次字段命中数，不能推广为 100% 识别或脱敏准确率。高置信度漏字仍可能不触发复核，用户必须核对姓名、日期、编号和联系方式。

默认策略优先节省普通页成本，检测结果稀疏、字号过小或低置信度时最多复核一次。可靠 PDF 文字层直接提取而不加载 OCR，扫描及混合页才识别。推理串行、模型单份复用，单次 C++ 推理无法中途抢占，取消在阶段边界生效。后续只有用真实且获授权的多字体证书集验证到持续误识别时，再评估更重的本地模型。
