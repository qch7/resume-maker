# 系统日志

顶部“系统日志”打开独立的全宽观测区域。活动轨道按 API、AI 消息、工具、任务、业务操作、系统和浏览器分行展示；点击标记定位事件，点击时间线记录查看参数、结果、异常和关联信息。界面沿用浅色及深色主题。

## 使用

- 关键词搜索覆盖标题、详情、来源、请求、任务和会话标识，可组合类型、级别及起止时间筛选。
- 默认开启“隐藏轮询 200”，过滤 `GET /api/state`、`GET /api/honors` 和 `GET /api/templates/analyses/*/progress` 的成功响应及同一请求中的普通 API、业务记录。错误、警告、AI、工具和任务活动仍显示；未完成请求暂时可见，200 响应到达后自动撤回普通记录。原始日志继续完整保存。
- “日志设置”默认开启“隐藏例行维护”，隐藏 `template_library.purge_expired` 及其内部 `template_library.state` 的普通开始、完成记录；独立的模板库读取、实际删除、警告和错误仍显示。已有浏览器设置自动补上此默认值，可随时关闭并保存偏好；历史和新日志、计数、搜索、翻页及导出均按该规则过滤，关联排查仍展示完整记录。
- 右上角“日志设置”可修改轮询路径，每行一条，`*` 匹配可变路径，不含查询参数；空规则表示不过滤。开关、路径和面板尺寸保存在当前浏览器，下次进入自动恢复。计数、搜索、翻页和导出使用相同过滤规则；查看“关联请求”时临时显示完整链路。
- 拖动轨道下方或列表和详情之间的分隔条调整大小；窄窗口自动改为上下分区。方向键微调，双击或 Enter 复位，也可在日志设置中重置布局。列表行高为 32 px，时间条件收在“时间筛选”中。
- 点击详情中的关联请求，追踪同一次 API 请求及它启动的后台任务；任务、会话和项目 ID 在详情中保留。
- “暂停”只暂停界面追加，后台仍持续记日志；“跟随最新”控制自动滚动，向上浏览或展开详情后停止跟随。
- 默认读取最近 200 条，实时增量按游标补齐；“加载更早记录”暂停更新并向前分页。浏览器最多保留 3,000 条摘要，详情按需读取，长列表只渲染可见窗口。
- “导出”按当前筛选生成 JSONL 快照，包含详情，范围覆盖所有仍保留的匹配记录；“复制 JSON”只复制选中事件。

## 记录范围

| 类别 | 内容 |
| --- | --- |
| API | 全部 `/api/` 业务请求的开始、请求头、查询参数、请求/响应摘要、状态码、耗时、异常栈；认证拒绝和校验失败也记录 |
| AI | 用户消息、已保存的助手回复、模型执行输入、脱敏后的上下文、CLI 系统指令、CLI 公开消息及用量 |
| 工具 | CLI 工具调用开始和完成事件、调用 ID、名称、参数、返回结果及失败状态 |
| 任务 | 项目分析、会话回复、模板分析/修复、证书识别的进度和成功、失败、取消结果 |
| 业务操作 | 项目、经历、修订、会话、简历、导出、模板库、荣誉和预览服务的公开入口及关键后台边界 |
| 系统 | 服务启停、OCR、Word 进程、CLI 进程、标准错误输出，以及当前业务上下文内的 Python 警告和错误 |
| 浏览器 | 未捕获 JavaScript 异常、未处理 Promise 错误及业务 API 网络失败；服务不可达时无法回传此记录 |

日志接口本身不写 HTTP 轨迹，防止查看日志引发无限增长。静态资源访问、任意第三方库内部函数及其他本机应用不在采集范围。CLI 仅记录其实际公开的事件，无法还原供应商未公开的数据。没有改变模型工具权限和隐私网关。

首次接入按原始时间补录保留范围内的历史消息和已有任务事件，并记录来源为 `history`；旧版本未保存的工具参数及结果无法补回。任务或会话删除不会同步删除已保存的调试轨迹，轨迹按统一保留策略到期清理。

## 存储及边界

日志独立存放在 `<数据目录>/logs/activity.sqlite`，不会升级或重建 `resume.db`。默认保留最近 30 天、约 50,000 条事件，启动时及每 100 次写入清理一次，最多短暂多出 99 条；删除的 SQLite 页面由后续日志复用。日志不随资料 ZIP 备份，恢复前的目录仍按原恢复流程保留。

鉴权字段、Cookie、常见令牌、私钥、URL 用户名密码和当前实例/供应商凭据统一遮盖。日志含本机真实资料，脱敏模型上下文也单独保留以便比较；日志不会回传给模型。上传和下载的二进制只记录类型、路径或字节数，不保存原始像素。

HTTP 文字正文最多记录前 32 KiB；单条活动详情约 256 Ki 字符，集合最多 1,000 项、嵌套最多 16 层，达到边界会留下明确截断标记。模型输入及工具结果通常可以完整展示，超大内容按上述边界保留摘要。日志写入失败不回滚业务操作，界面显示失败计数和最近原因。

## 扩展及验证

应用工厂集中注册 `instrument_service`，公开服务方法自动记录开始、结束、参数、结果和异常；后台执行方法明确列入 `background`。入队前调用 `remember_task` 保留请求关联，在线程入口恢复任务上下文；集成层使用 `operation` 或 `record` 补充具体活动。实例隔离由 `ContextVar` 和每实例日志对象保证，无日志上下文时维持原函数行为。

日志查询支持 `hide_polling`、换行分隔的 `polling_paths` 和 `hide_maintenance` 参数，API 调用方不传开关时保持完整记录。例行维护按来源和父操作标识识别，避免误过滤用户主动读取模板库。增量响应的 `hidden_trace_ids` 标识本批次成功完成的轮询，客户端据此撤回先到的普通记录，避免刷新后残留请求开始事件。

`tests/test_activity.py` 覆盖认证、状态、异常栈、凭据遮盖、稳定分页、字面搜索、导出、历史补录、重启、并发实例隔离、保留策略、日志故障和真实 CLI 格式的工具轨迹，以及成功轮询过滤、错误保留、路径规则及跨批次撤回。前端测试覆盖摘要去重、窗口限制、时间定位、撤回和设置恢复。完整验收仍运行 `uv run python scripts/check.py`。
