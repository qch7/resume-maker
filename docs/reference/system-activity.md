# 系统日志

顶部“系统日志”打开独立的全宽观测区域。活动轨道按 API、AI 消息、工具、任务、业务操作、系统和浏览器分行展示；点击标记定位事件，点击时间线记录查看参数、结果、异常和关联信息。界面沿用浅色及深色主题。

日志界面位于 `plugin_packages/ext_activity_ui/client/`，采集服务及路由位于必需的 `plugin_packages/sys_activity/`。关闭或移除“日志界面”只撤销页面贡献，后端仍按已保存的采集类别写日志；暂停采集需在系统日志设置取消类别并保存。历史日志不会因界面插件缺失而删除。

## 使用

日志配置统一放在“工作台设置 → 系统日志”，日志页右上角的设置按钮可直达该页。切换设置标签保留当前输入，保存隐藏规则和重置日志布局后同步更新日志页。

- “工作台设置 → 系统日志 → 采集类别”决定后端记录哪些类别，默认仅勾选“AI 消息”。可以按需开启 API、工具、任务、业务操作、系统和浏览器，或取消全部勾选暂停采集。点击“保存”后立即用于后续日志，配置按数据目录持久保存，所有窗口共享，重启后保留。
- 未勾选类别的所有级别均跳过，包括警告和错误，不写入磁盘，也不能通过搜索或关联请求找回。既有日志和业务 AI 会话记录保留；需要完整排查时先开启相应类别。“恢复默认”将采集类别和隐藏规则一起恢复到默认值，仍需点击保存。
- 默认显示本地时间今天的日志，跨过本地零点或重新激活页面时自动更新日期。右侧时间按钮展开浮层，可选“今天”“全部时间”或修改起止时间，不额外占用一行工具栏。
- 关键词搜索覆盖标题、详情、来源、请求、任务和会话标识，可组合类型、级别及起止时间筛选。类型和级别都支持下拉勾选多项，同一筛选内任一项匹配即可；未选具体项时显示全部。
- 默认开启“隐藏轮询日志”，按“工作台设置 → 系统日志 → 隐藏规则”的统一文本规则过滤。每行填写 API 路径、操作名或 `类型:事件`，支持 `*`，路径不含查询参数。路径默认 GET，也可写 `POST /api/templates/analyses/*/review`；空规则表示不过滤。默认规则从后端配置读取，界面保存的自定义规则优先；可点“恢复默认”并保存，继续继承文件配置。
- 默认轮询范围包括状态、荣誉、模板分析进度和详情、POST 模板自动校验、POST 窗口心跳、GET 插件变更进度及下载列表。匹配路径的普通请求和成功响应全部隐藏，首次响应和内容变化后的正常响应也不显示。警告、错误和至少 1 秒的慢操作保留；HTTP 200 的异常信息或响应正文中非空 `errors` 仍显示。
- 匹配轮询的请求开始立即隐藏，避免等待响应时短暂插入一行；成功响应到达后撤回同一链路的普通读取步骤。关键词搜索也遵守隐藏规则；关闭隐藏开关或查看关联请求可恢复已采集的完整链路，原始记录不删除。
- 普通只读操作默认隐藏，包括工作台状态、项目/修订/模板/会话读取、模板分析数据/来源/项目读取、荣誉读取和模板库状态/例行维护。保存、删除、识别、预览等实际操作仍显示；警告、错误及耗时至少 1 秒的操作不受这些隐藏规则影响。
- `ai:thread.started` 和 `ai:turn.started` 默认隐藏 CLI 握手阶段；消息正文、脱敏上下文、系统指令、用量、工具活动和失败继续显示。操作名规则只匹配业务操作的开始/完成事件，`类型:事件` 可配置 AI、任务、系统或浏览器的普通事件。
- 筛选不改动原始日志，计数、搜索、翻页和导出使用相同过滤规则；查看“关联请求”时临时显示已采集的完整链路。
- 拖动轨道下方或列表和详情之间的分隔条调整大小；窄窗口自动改为上下分区。方向键微调，双击或 Enter 复位，也可在工作台的系统日志设置中重置布局。列表行高为 32 px，空类别轨道默认隐藏，轨道计数固定在顶部。阶段使用简短中文，完整事件名和时间可悬停查看。
- 点击详情中的关联请求，追踪同一次 API 请求及它启动的后台任务；任务、会话和项目 ID 在详情中保留。
- “暂停”只暂停界面追加，后台仍按采集类别记日志；“跟随最新”控制自动滚动，向上浏览或展开详情后停止跟随。
- 默认读取最近 200 条，实时增量按游标补齐；“加载更早记录”暂停更新并向前分页。浏览器最多保留 3,000 条摘要，详情按需读取，长列表只渲染可见窗口。
- “导出”按当前筛选生成 JSONL 快照，包含详情，范围覆盖所有仍保留的匹配记录；“复制 JSON”只复制选中事件。
- “工作台设置 → 系统日志 → 删除日志”可选择“今天之前”或“全部日志”，确认后永久删除对应范围，包括被筛选隐藏的记录。成功后显示删除条数并刷新列表；简历资料、AI 会话原文不受影响，新活动按采集类别继续记录。

## 独立配置文件

默认规则集中在 `src/resume_maker/infrastructure/activity_rules.json`，原有 API、业务读取和 AI 事件规则完整保留。前端不再内置规则清单。

日常调整时复制 [日志规则示例](../../examples/activity-rules.json) 为自己的 `activity-rules.json`，在 `.env` 中指定：

```dotenv
RESUME_MAKER_PLUGIN_CONFIG=./activity-rules.json
```

修改 JSON 中 `startup` 操作的 `value` 数组，每项填写一条规则；空数组表示默认不隐藏。示例只配置 `sys.activity.hidden_rules`，可以合并进已有插件配置文件的 `startup` 数组。修改后重启服务并重新打开页面，后端发布有效规则，前端无需重新构建。文件规则继续遵循最多 100 条、4,000 字符的限制，无效语法会阻止配置生效。

页面“恢复默认”使用当前文件配置。面板尺寸和隐藏开关继续单独保存；界面编辑规则后保存为明确覆盖，恢复默认并保存后移除该覆盖。只采用当前配置契约，不识别或迁移旧默认规则。

隐藏规则只控制列表、计数、搜索及导出，不停止轮询，也不改变日志采集类别。

## 记录范围

下表列出各类别开启后的范围；默认只采集 AI 类别，其余类别需要在工作台的系统日志设置中开启。

| 类别 | 内容 |
| --- | --- |
| API | 全部 `/api/` 业务请求的开始、请求头、查询参数、请求/响应摘要、状态码、耗时、异常栈；认证拒绝和校验失败也记录 |
| AI | 用户消息、已保存的助手回复、模型执行输入、脱敏后的上下文、CLI 系统指令、CLI 公开消息及用量 |
| 工具 | CLI 工具调用开始和完成事件、调用 ID、名称、参数、返回结果及失败状态 |
| 任务 | 项目分析、会话回复、模板分析/修复、证书识别的进度和成功、失败、取消结果 |
| 业务操作 | 项目、经历、修订、会话、简历、导出、模板库、荣誉和预览服务的公开入口及关键后台边界 |
| 系统 | 服务启停、OCR、Word 进程、CLI 进程、标准错误输出，以及当前业务上下文内的 Python 警告和错误 |
| 浏览器 | 未捕获 JavaScript 异常、未处理 Promise 错误及业务 API 网络失败；服务不可达时无法回传此记录 |

日志接口本身不写 HTTP 轨迹，防止查看日志引发无限增长。静态资源访问、任意第三方库内部函数及其他本机应用不在采集范围。CLI 仅记录其实际公开的事件，无法还原供应商未公开的数据。没有改变模型工具权限和隐私网关。

CLI 进程标题区分“版本检查”和“模型调用”，开始、完成、失败及标准错误输出采用同一名称，来源仍为 `cli.process` 或 `codex-cli`。CLI 的诊断条目展示具体 `message`，`item.type=error` 标记为错误，避免只显示含义不明的 `error`。配置目录和临时文件目录分开，并关闭已启用开发功能的通用启动提示；其他标准错误输出和执行失败继续记录。

首次接入按采集类别和原始时间补录保留范围内的历史消息和已有任务事件；未勾选类别不参与补录，之后开启该类别仅采集新事件。补录记录的来源为 `history`，全部写入成功才标记完成，部分失败在下次启动重试，已写入记录按来源去重。手动删除日志后停止历史补录，避免重启带回已删除记录。旧版本未保存的工具参数及结果无法补回。任务或会话删除不会同步删除已保存的调试轨迹，轨迹按统一保留策略到期清理。

## 存储及边界

日志和采集类别配置独立存放在 `<数据目录>/logs/activity.sqlite`，配置使用既有元数据表保存；旧日志库没有配置时也默认仅采集 AI 消息。未启用类别在正文序列化和数据库连接之前跳过，不推进游标、不计入写入失败。配置提交和日志写入串行，保存失败保留原策略，业务库 `resume.db` 的结构保持不变。默认保留最近 30 天、约 50,000 条事件，启动时及每 100 次写入清理一次，最多短暂多出 99 条；删除的 SQLite 页面由后续日志复用，已有日志文件不会因缩小采集范围而立即变小。日志不随资料 ZIP 备份，恢复前的目录仍按原恢复流程保留。

手动删除仅清理日志记录，不移除采集配置、日志库及历史补录标记，重启后不会重新导入已删除的历史消息。日志游标单独保存在元数据中，删除或自动清理后仍递增，避免实时增量请求漏收新记录。

列表、计数、分页和导出采用相同隐藏规则。计数按日志快照、持久删除代次和筛选条件缓存，最多 32 组；新记录、删除和保留清理立即失效，包括同库另一个实例的操作。没有新日志的空增量不重新扫描历史及撤回链路，新增撤回只读取游标后的响应。旧版本用于轮询合并的 `activity_responses` 派生索引在启动时移除，不删除原始日志或游标；后续不再计算轮询分组及重复次数。历史分页会保留同期撤回的链路，避免旧快照重新带回已隐藏步骤。

鉴权字段、Cookie、常见令牌、私钥、URL 用户名密码和当前实例/供应商凭据统一遮盖。日志含本机真实资料，脱敏模型上下文也单独保留以便比较；日志不会回传给模型。上传和下载的二进制只记录类型、路径或字节数，不保存原始像素。

AI 调用的开始阶段标为“原始输入”，详情明确提示它是脱敏前的本机入参；`context` 标为“脱敏输入”；完成阶段标为“本机还原”。本机原始输入和还原结果含真实资料，不代表发给供应商的内容。

HTTP 文字正文最多记录前 32 KiB；单条活动详情约 256 Ki 字符，集合最多 1,000 项、嵌套最多 16 层，达到边界会留下明确截断标记。模型输入及工具结果通常可以完整展示，超大内容按上述边界保留摘要。日志写入失败不回滚业务操作，界面显示失败计数和最近原因。

## 扩展及验证

应用工厂集中注册 `instrument_service`，公开服务方法自动记录开始、结束、参数、结果和异常；后台执行方法明确列入 `background`。入队前调用 `remember_task` 保留请求关联，在线程入口恢复任务上下文；集成层使用 `operation` 或 `record` 补充具体活动。实例隔离由 `ContextVar` 和每实例日志对象保证，无日志上下文时维持原函数行为。

日志查询的 `category` 和 `level` 支持逗号分隔多值；统一隐藏开关为 `hide_polling`，`hidden_rules` 为换行分隔的规则，最多 100 条、4,000 字符。未传规则时采用当前日志实例的配置；显式空规则表示不过滤。匹配规则时隐藏未完成请求的普通开始事件，并保留慢操作和实际修改事件。成功轮询按路径、方法及 HTTP 200/304 识别，警告和错误保留。API 调用方不传开关时保持完整记录。增量响应的 `hidden_trace_ids` 标识本批次成功完成的轮询，客户端据此撤回普通请求、响应及读取步骤，保留慢操作、警告、错误和实际修改事件。未知查询参数返回 422。

`GET /api/activity/defaults` 返回当前有效的 `hidden_rules` 字符串数组，供工作台启动及设置页恢复默认使用，沿用本机认证且不记录自身请求。

`GET /api/activity/settings` 读取采集类别，`PUT` 接受显式的 `categories` 数组（最多 7 项），可选值为 `api`、`ai`、`tool`、`task`、`service`、`system` 和 `client`。空数组暂停采集，重复项去重，未知类别和无效结构返回 422；接口沿用本机认证且不记录自身操作。

`DELETE /api/activity` 使用同一本机认证，请求体必须显式提供 `before`：带时区时间表示只删除该时刻之前的记录，`null` 表示删除全部。接口返回 `deleted` 条数，不采用列表筛选或隐藏规则。

`tests/test_activity.py` 覆盖认证、状态、异常栈、凭据遮盖、稳定分页、字面搜索、导出、历史补录、重启、并发实例隔离、保留策略、日志故障和真实 CLI 格式的工具轨迹，以及成功轮询过滤、错误保留、路径规则及跨批次撤回。`tests/test_activity_capture.py` 覆盖默认 AI 采集、写入前跳过、接口保存、空选、鉴权、无效输入、保存失败、旧日志库和历史补录。前端测试覆盖摘要去重、窗口限制、时间定位、撤回和设置恢复。完整验收仍运行 `uv run python scripts/check.py`。


## 插件归属

采集、凭据遮盖和落盘属于必需的 sys.activity；完整日志浏览区域由 ext.activity-ui 贡献，停用浏览区域不会改变已保存的采集规则或清空历史。活动设置仍可从系统设置进入。插件的公开服务和后台任务保留原请求关联，业务任务记录与统一执行记录使用相同实体标识。

插件初始化、提供方附接、例行工作台快照等内部调用通过 sdk.observation.internal 标记，不重复生成用户业务操作。activity.presenters 客户端贡献只接收已经遮盖的冻结事件，用于显示标题和文本字段，不修改原始日志。
