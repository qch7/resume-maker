# 开发规范

本文件适用于整个仓库。开始修改前阅读对应规则；当前功能、协议和实现分别见使用指南、架构说明及 reference 下的文档。

## 技术栈和目录

后端使用 Python 3.12+、FastAPI、Pydantic 和 SQLite，前端使用 React、TypeScript 和 Vite，Node.js 要求 22.16+，Python 依赖由 uv 管理。

| 目录 | 主要内容 |
| --- | --- |
| `src/resume_maker/api/` | 应用工厂、依赖注入、HTTP 路由、请求模型和本机访问校验 |
| `src/resume_maker/core/` | 运行配置和业务异常 |
| `src/resume_maker/domain/` | 数据模型、经历规则、栏目结构和模板映射契约 |
| `src/resume_maker/plugin_packages/<slug>/` | 插件清单、入口、服务、路由、查询、私有适配器、资料声明和客户端 |
| `src/resume_maker/infrastructure/` | SQLite 访问、初始结构、实例锁、备份和恢复 |
| `src/resume_maker/integrations/` | 多个插件复用的隐私、源码访问和文档工具；具体 CLI、OCR 模型和 Word 执行归属插件包 |
| `src/resume_maker/integrations/word/` | 多个文档引擎和导入器复用的 OOXML、布局及恢复工具 |
| `frontend/src/plugins/` | 客户端加载器、作用域、贡献注册表和公开 SDK 入口 |
| `frontend/src/shared/` | 通用控件、hooks、网络、本机缓存和 API 类型 |
| `frontend/src/styles/` | 宿主基础样式；功能样式随所属插件独立构建 |
| `tests/`、`frontend/tests/` | 按功能分组的后端回归测试和前端逻辑测试，后端共享辅助代码在 `tests/support/` |
| `scripts/` | 启停、检查、构建和模板评测脚本 |

后端依赖约束由 `scripts/check_quality.py` 检查：`core` 独立于业务模块，`domain` 不依赖存储或适配器，`infrastructure` 和 `integrations` 不导入 `services` 或 `api`，`services` 不导入 `api`。

Provider 和隐私存储由独立插件组合，`api/app.py` 只创建 Host 和路由快照；任务队列不负责其他服务的依赖装配。适配器显式实现 `Provider` 中的图片能力、任务隐私副本及 OCR 登记，不用属性探测绕过契约。设置及隐私规则的事务放在对应服务，路由只负责 HTTP 输入输出。

前后端宿主和插件均不能导入另一插件的私有实现。后端按清单消费 SDK 服务及贡献，前端通过 `@resume-maker/plugin-sdk/<子入口>` 消费公开类型、控件和注册接口。目录搬迁后继续检查包内 services、integrations、routes 的原有分层。通用草稿提交通过 `shared/lib/draftRegistry.ts` 协调。

依赖检查同时覆盖 Python 包入口导入、前端重导出及字面量动态导入，不能通过改写导入语法绕过模块边界。

## 注释规则

- 使用简短、自然的中文陈述句，尽量一句话说明用途、原因或必要条件，写不下时分成多行。
- 直接描述实际行为，删掉空泛提醒、重复解释和宣传式措辞。
- 避免“不是……而是……”或“并非……而是……”等对照式表达，并列内容使用顿号或“和”，不用“与”字串联。
- Python 函数保留简短中文 docstring，前端具名函数保留紧邻声明的中文说明，简单回调不重复解释代码。
- 注释末尾不加句号，减少逗号和分号堆叠，过长时先压缩表述再分行。
- 保留并发校验、事务、取消、文件路径和进程回收中的必要条件，修改行为时同步更新注释。

注释示例：

```python
"""根据父修订关系计算历史图坐标"""
```

```typescript
/** 等待当前 Word 请求完成后处理最新输入 */
```

## 业务规则

- 经历修订一经保存即不可变，发布和恢复通过新修订完成，历史关系使用真实父版本。
- 编辑、增删和排序先写草稿，整段提交才生成版本，内容没有变化时清理已确认草稿即可。
- 保存和删除校验草稿版本及分支头，并在同一事务中完成引用校验和写入，冲突时保留用户输入。
- 简历固定保存 `revision_id` 和 `highlight_ids`，经历更新后由用户选择是否用于当前简历。
- 单字段、单条经历和个人信息的保存各自保留其他未提交草稿，迟到响应不得覆盖后续输入。
- AI 结果先作为建议保存，采用前再次核对原文和当前状态，取消后的结果不得发布。
- 项目、经历分支、会话和应用实例分别隔离，来源分析只读关联目录并保存可追溯证据。
- 荣誉内容按稳定来源标识同步，各份简历保留自己的显隐、排序和备注，历史导出保持原样。
- 模板填充使用已确认的节点、精确引文和范围，未识别原文、照片缺位或栏目冲突需要明确报告。
- 模板补位、检查、试填和导出复用现有入口，在副本中处理并保留原文件，规则不得依赖某份简历的姓名、文件名或固定节点编号。
- Word 排版在独立子进程中执行，串行调用受全局状态影响的转换器，回收前核验进程身份。
- 数据库调整同步完整初始结构、插件资料目录册和测试；当前结构为 v9，运行时只接受当前版本。开发资料先备份、离线转换并验证恢复，再移除旧格式支持；外部插件表由停机维护初始化或升级。

## 数据和运行环境

- 服务保持本机单用户运行方式，保留回环监听、Host、Origin 和实例令牌检查。
- 源码运行默认使用 `data/`，开发和验收使用临时目录，通过 `--data-dir` 或 `RESUME_MAKER_DATA_DIR` 指定。
- 源码运行沙箱使用项目根目录下的 `.local/sandbox/`，安装包使用用户目录下的 `.resume-maker-sandbox/`，不随启动位置或数据目录设置改变。沙箱须排除于 Git 和源码读取范围，直接选择其子目录也不能读取，任务结束只清理本轮副本。
- 测试使用合成资料、临时数据库和可控 Provider，真实供应商调用及真实资料发送以用户授权范围为准。
- 个人简历、证书、照片、数据库、聊天记录、密钥和生成产物不进入 Git 提交。
- 文件操作先核验路径范围和链接，保留原始源码及导入文件，清理只针对当前任务或当前实例拥有的产物。
- 详细约束见 [SECURITY.md](../.github/SECURITY.md)。
- 日志写到数据目录的 `logs/activity.sqlite`，不修改业务库版本且不进入资料 ZIP 备份；日志只在本机显示，凭据统一遮盖，大正文明确截断。新服务入口在应用工厂注册观测包装，新后台线程须在入队前登记任务关联；跨进程细节通过父进程记录，禁止把进程环境或鉴权原文写入日志。具体边界见 [系统日志](reference/system-activity.md)。
- CLI 的 `control/codex-home` 和 `control/tmp` 保持同级，任务临时文件不能包含 CLI home。日志标题区分版本检查和模型调用，诊断显示具体消息；开发功能启动提示通过 CLI 配置关闭，其他异常继续记录。

## 插件实现约束

- 内置插件独立目录统一放在 `plugin_packages/<slug>/`，slug 是插件 ID 将点及连字符改为下划线。发现和构建扫描 manifest.json / package.json；产品组合归属写在包内，禁止在宿主新增可选 ID 清单、入口导入或私有文件转发。
- 删除可选代码目录后重新构建及启动应自动阻断缺依赖的消费者，保留已存资料和用户选择；显式要求完整组合时仍严格报错。系统必需目录缺失必须明确拒绝启动。运行中的卸载仍先执行原有排空流程，不能直接删正在执行的文件。
- 仅多个消费者复用的工具和稳定数据契约进入宿主共享层；共享工具通过公开参数消费可选实现，不能加载具体模型、供应商或平台插件。荣誉识别策略由识别插件注入，库服务负责事务和任务收尾。
- 当前协议见 `docs/reference/plugin-sdk.md`，装配和生命周期见 `docs/architecture.md`。清单声明必须由实际实现和测试验证。
- 系统插件依赖闭包只包含系统职责及必需提供方，隐私和 sandbox 不可选。服务通过声明的能力消费，API 依赖必须与路由所有者清单一致。
- 注册、订阅、样式、RPC 和后台资源归属插件作用域；清理失败保留依赖。附接别的服务时声明 enhances，纳入反向排空。
- 生产模型任务、荣誉识别和模板分析交给 sys.jobs；取消后等待实际执行结束，旧代次结果不可发布。实际进程只经 sandbox 授权及 execution 执行。
- 保留普通编辑的未知扩展资料。停用、缺包和卸载不得删除资料；业务附件使用 assets，外部插件私有目录通过持久描述参与备份。
- 新增插件及客户端贡献应有组合、失败、数据恢复及真实用户路径验收。前端公开插槽位于 plugins/slots.ts，不能从组件实现推导公共 API。
- 文档引擎及渲染器使用 `sdk/documents.py` 和公开贡献注册，接收冻结输入；成品记录明确引擎标识和版本。管理通道不能被业务排空冻结，系统插件重建保留唯一变更协调器。
- 资源引用删除与业务写入共用事务，失败暂存和墓碑仅通过显式维护计划回收；已发布资料不因插件停用而清理。
- 客户端命令、字段编辑器和工作流贡献通过 `ClientContext.contribute` 注册并声明清单；扩展资料只更新所属命名空间，必须进入已有草稿、保存及导出新旧比较。命令卸载等待实际执行结束，异常组件只影响当前贡献。

- 模板和证书导入使用 `sdk/imports.py`、`documents.importers` 贡献及统一注册表。实际内容探测不调用模型；冲突须明确选择，返回不可变字节并完整校验页数。历史原件保存处理器及包摘要，重试拒绝静默换版本。集合消费者声明 `consumes`，纳入提供方变更的请求和任务排空。
- 停用和宿主关闭使用包含 consumes、enhances 的完整消费图，先完成受影响实例的停止屏障再释放资源；消费环共同排空，停止失败不得释放该轮资源。整页切换前须取消并等待全部客户端命令实际结束，再刷新最终草稿，超时保持未确认。
- 宿主退出先拒绝新任务、取消并等待现有执行实际结束，再清理残留子作用域及父资源；等待期间不得持有任务清理需要的父作用域锁，重复关闭应安全。所有应用内刷新按钮共用窗口协调器，命令结束后才保存草稿或处理存储冲突，超时保留页面并允许重试。
- 旧窗口刷新遇到保存失败时，须读取当前能力确认代次已变化且宿主就绪，再核验未保存输入已进入浏览器恢复副本；所有草稿回调收尾后才允许刷新。不得提升旧窗口写入代次或自动重放恢复副本，同代次冲突及副本保存失败仍阻止刷新。
- 准备计划过期仍可取消任务及退出；取消其他预览不能解除当前计划冻结。管理页恢复普通启停和包升级的活动计划，刷新后的窗口加入确认屏障，旧窗口恢复副本仍需明确保留。

- 官方启动器通过稳定监督器执行需要重启的变更；候选包、环境和资料先在副本试运行。只有健康观察完成才提交成功；资料已迁移时禁止自动把旧代码开放给新资料。
- 内置数据结构由清单 data.schemas / data.relations 声明，按选择建表；业务删除使用持久引用规则，缓存失效使用事务 after_commit。模板、证书、来源证据和成品通过 assets 发布，离线迁移须核对原件清单及摘要后清理旧副本。

## CLI 和脱敏约束

隐私 CLI 不按具体版本号或预发布后缀拒绝运行，严格配置、受控模型目录及工具权限检查保持生效。调整 CLI 兼容性须通过真实 CLI 对本机假服务的工具边界验收，不得降级为宽松配置或普通 shell。OCR 评测只使用合成材料，复现命令见开发指南，指标不能推广为实际准确率。

模型名称及思考强度不使用供应商值白名单，强度只校验标识格式并在前端允许自定义输入，实际支持范围由 CLI 和模型判断。Profile 按完整 TOML 键查找，独立配置文件保持 CLI home 内的路径边界，不能以放开名称为由允许路径穿越。

工具边界必须同时约束功能开关和模型目录元数据，并覆盖普通模型、GPT-5.5、GPT-6-Astra。Windows 子进程须挂起创建、加入 Job Object 后再恢复；源码副本写入须保持原始换行及引用行号。真实供应商验收仅使用合成资料，抓包及原件放入忽略目录，报告不得包含鉴权。

编号脱敏须覆盖完整范围和 OCR 分块，短数字敏感词不能只遮盖长编号的一部分。新增规则同时验证成绩、日期、源码、固定协议字段和本机还原能力；替换次数不代表识别完整度。

结构化敏感值按业务语义登记：`personal.name` 是姓名，通用 `name` 不自动作为身份；教育学校需保护，专业、职位、成绩和证书名称保留。业务字段仍服从显式敏感词、身份格式及低置信度 OCR 规则。设置中的隐私保护独立分页，切换页面保留输入，预览使用已保存规则；详细范围和发送记录按需展开。

任务上下文复制及 OCR 登记须分别保留身份值和不可还原的凭据集合。CLI 仅接受 Responses 协议，工具权限校验覆盖开始、更新及完成事件；POSIX 沙箱父目录必须属于当前账户且权限为 0700。历史日志仅在全部补录成功后标记完成，失败重试按来源去重，手动删除须阻止后续历史补录。
