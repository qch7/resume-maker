# Resume Maker 产品与技术方案草案

日期：2026-09-12。状态：讨论稿，尚未确定全部实现细节。

Resume Maker 将本地项目材料整理为有来源、有版本的项目经历，再通过勾选、排序和选择文案版本组合简历，导出可编辑的 Word。第一阶段供个人在本机使用，优先调用本机 Codex；后续通过多个 Provider 接入模型 API，并逐步实现自己的简单 Agent。

用户追加确认：每一条项目亮点（如“多 Agent 编排：……”）都必须支持单独人工编辑和保存；左侧每个项目经历独立管理 AI 会话，聊天记录、上下文和待采用的修改建议不能跨项目混用。会话采用类似 ChatGPT Web 的侧边栏列表，不使用下拉框切换。

## 已确认需求与现场情况

- 应用目录为当前 resume-maker，目标远端为 https://github.com/qch7/resume-maker.git 。本次检查时本地应用目录为空，远端 ls-remote 成功但未返回引用。
- 项目集合中有 bidmind、GEWU-The-Everlasting-Light、go_exchange_app、mo-bao、sky-take-out、syncraft、TrustGuard 共 7 个顶层项目目录。
- 6 个顶层项目带 Git 标记；TrustGuard 下另有 5 个仓库。因此，一个逻辑项目必须能够关联多个代码来源，也要容纳没有 Git 的普通目录。
- 部分项目没有顶层 README，不能将生成流程建立在 README 必然存在的假设上。
- 参考简历的项目经历是普通正文段落，但整份文档包含文本框、浮动图形和 4 个分节，尚未设置供程序填充的内容控件。以上是 OOXML 结构检查结果，不代表已完成导出排版验证。
- 本机可找到 Codex CLI，版本为 0.154.0-alpha.6.2。已核对帮助和官方非交互文档；尚未发起实际模型分析调用。

## 推荐产品形态

先做本地 Web 应用：启动器启动本机服务并打开浏览器。前后端在代码层分离，在使用和部署层作为一个工具提供；正式运行时由本机服务直接提供构建后的前端文件。

推荐 Python + FastAPI 负责项目扫描、Git、Codex 子进程、数据和 Word 导出；React + TypeScript + Vite 负责项目库、文案编辑与组合交互；SQLite 管理个人数据。后台任务先用进程内受控队列，不引入 Redis、Celery 或服务器数据库。

| 方案 | 适配情况 | 建议 |
| --- | --- | --- |
| 本地 Web，Python 服务 + React 界面 | 可直接读取本地项目和调用 Codex，文档处理方便，UI 易迭代 | 第一阶段采用 |
| Electron 或 Tauri 桌面应用 | 有独立窗口和原生目录选择，但增加打包、更新及后端集成工作 | 核心流程稳定后再评估 |
| PySide6 等原生 Python 窗口 | 单一语言、文件访问方便；富文本和复杂预览交互需要额外开发 | 可行备选 |
| 云端 Web | 需要项目上传或本地连接程序才能访问用户磁盘及本机 Codex | 不匹配当前个人本机需求 |

浏览器直接读取任意磁盘绝对路径受限制，目录访问由本机后端实现。第一版可以输入、粘贴路径并浏览已授权项目根目录，无需为了目录选择立即引入桌面框架。本机服务只监听回环地址，并校验会话令牌、Origin 和允许访问的根目录。

## 用户操作流程

1. 添加一个或多个项目集合目录，扫描可用项目，确认多仓库项目的归组。
2. 为项目补充本人角色、负责模块、参与日期、成果材料与不希望对外展示的内容。
3. 选择项目和 Provider，发起分析；查看进行状态、日志、错误并能取消任务。
4. 查看 AI 生成的项目事实与证据，补齐待确认信息，生成项目经历草稿。
5. 单独编辑任意亮点的标题和正文并保存；也可在本项目的 AI 会话中讨论整段经历或指定亮点，检查并采用 AI 修改建议，再保存新版本。
6. 新建一份简历方案，勾选经历及具体版本，选择亮点、调整顺序，套用模板。
7. 导出 Word，记录本次采用的模板版本和全部经历版本。再次打开这份方案时保持原来的组合。

工作台建议三栏：左侧为按项目分组的会话侧边栏，中间为聊天或经历编辑，右侧为当前简历预览。左侧顶部提供“新会话”，其下显示当前归属项目；每个项目名称下纵向排列该项目的会话标题，支持展开/收起，当前会话高亮，最近活动的会话排在该项目列表前面。点击会话直接打开聊天，点击项目名称打开该项目的经历编辑；项目旁的勾选框仅控制是否加入简历。

中间保留“经历内容 / AI 会话”标签，点击亮点的“让 AI 修改”后定位到本项目当前会话并附带该条亮点。聊天区标题显示当前会话名称，不再放会话选择下拉框。窄屏可将侧边栏收起或堆叠，会话入口仍采用列表。经历版本、单轮讨论范围等字段可以继续使用下拉框；用户排除的是会话导航下拉框。

## 逐条人工编辑与保存

- 每条亮点提供独立的“编辑”“保存此条”“取消编辑”“让 AI 修改”。编辑时可分别修改加粗的小标题和正文，勾选框继续控制是否加入当前简历。
- 标题、技术栈、项目简介、参与时间等项目字段也可人工修改，遵循相同版本规则。亮点支持新增、删除、排序。
- 输入过程保存为工作草稿，明确显示“有未保存修改”；切换项目、会话或版本不丢失草稿。正式应用将草稿保存在 SQLite，重启后可恢复；对同一字段的并发编辑使用基准版本检查。
- “保存此条”立即持久化这条亮点，并生成一个新的完整经历修订：复制基准修订，只替换这一条。用户不需要再按一个整页保存按钮。其他仍未保存的亮点留在草稿中，不被顺带发布；未改动内容不产生重复修订。
- 修改记录保留稳定亮点 ID、修改前后内容、来源（人工或 AI 建议）、时间、父修订及可选说明。可查看单条修改历史；恢复旧文案会生成新的经历修订。
- 保存经历和更新简历组合是两个动作。保存后提示可将当前组合更新到新版本；已保存的其他简历仍引用原修订。编辑中的文字不会悄悄进入最终导出。
- 用户改变了事实或数字时，可以同步补充事实来源；事实关联状态需要重新核对，旧证据不自动证明新文案。

## 每个项目的独立 AI 会话

每个项目默认有自己的主会话。打开 mo-bao 展示 mo-bao 的聊天历史，切到 TrustGuard 展示 TrustGuard 的历史；再切回时恢复原会话、输入草稿和待采用建议。项目暂时不勾选进简历时，其会话仍然可用。多仓库项目的会话关联整个逻辑项目，允许阅读该项目登记的全部来源快照。

会话归属项目，可以关联某种经历写法。第一版支持同一项目下新建多条会话并在侧边栏直接切换，例如“Agent 岗位版”和“后端岗位版”；后续增加重命名、归档等管理操作。新建会话继承项目关联，不继承上一条会话的聊天历史或输入草稿。切换经历修订不回退或清空聊天历史；收起项目分组也不结束后台任务。

一轮对话可以面向整个项目经历，也可以绑定某条亮点。输入区明确显示目标，例如“当前项目：mo-bao / 修改：多 Agent 编排”。请求携带所属项目 ID、会话 ID、经历基准修订 ID、亮点 ID、所用代码快照及当前人工编辑内容，不能依赖模型自行猜测。

AI 的回复可以是解释、追问或结构化修改建议。建议展示原文与建议文本，支持逐条采用、拒绝及继续修改；采用先更新可编辑草稿，“保存此条”才发布修订。用户已经修改过同一字段时，比较请求基准与当前草稿，提示冲突，不让迟到的 AI 回复覆盖人工内容。

程序保存聊天记录及每轮输入快照，而非只保存 Provider 的远端会话 ID。手工修改后的当前文本与修改摘要应随下一轮对话提供，使 AI 知道最新事实。保存经历不会自动发送 AI 请求。

任务结果始终按发起时的项目和会话入库；用户中途切到别的项目，也不能将流式消息追加到当前屏幕所属会话。可以显示其他项目“处理中”的状态。第一版全局单任务排队，同一会话的多轮请求必须按顺序执行。

## 内容模型与版本规则

项目经历的主数据采用结构化字段，而非单独的 Word 文件或一段不可拆分的 Markdown。每个项目可以有多个写法、长度及修订版本，Word 导出时再应用统一样式。

| 对象 | 核心内容 |
| --- | --- |
| Project | 稳定 ID、名称、标签、来源目录集合、角色、本人负责范围、参与日期 |
| SourceSnapshot | 多个仓库的完整 commit SHA、分支说明、工作区状态、纳入分析的文件清单与哈希、采集时间 |
| AnalysisRun | Provider、实际可获得的模型信息、提示词与 schema 版本、输入快照、任务状态、错误和用量 |
| ProjectFacts | 项目事实、代码或文档证据、用户补充事实、确认状态 |
| ExperienceDraft | 项目/写法/基准修订、各字段草稿、保存状态、修改时间 |
| ExperienceRevision | 不可变修订 ID、父修订、用途/方向、标题、技术栈、简介、亮点、关联事实及快照、作者来源 |
| Conversation | 所属项目、可选写法、标题、Provider、Provider 会话 ID、状态及上下文重建记录 |
| ConversationMessage / Turn | 会话、角色、正文、轮次、状态、基准修订、目标亮点、输入材料快照及去重 ID |
| ChangeProposal | 所属会话/轮次、目标字段或亮点、基准内容、建议内容、证据及采用状态 |
| ResumeComposition | 简历方案、基础信息版本、固定的经历修订 ID、选中亮点 ID、排序、模板版本 |
| TemplateVersion | 模板文件、内容插入位置、项目样式、版本及文件哈希 |
| ExportRecord | 简历方案快照、模板哈希、渲染器版本、生成文件哈希、时间及导出清单 |

代码版本、经历版本和简历组合版本分别管理。例如，同一份墨宝代码快照可以产生 Agent 方向 r3 与后端方向 r2；保存的简历引用固定修订，生成 r4 不会改变已经保存的简历。

同一经历下的“Agent 方向”和“后端方向”是不同用途的写法；每种写法有自己的修订历史。“精简/标准/详细”是内容长度配置，不应混同于代码版本。界面可以将它们集中呈现，但数据上保留区别。

每条亮点有稳定 ID。组合时取消某条亮点只改变组合；改写文案需要产生新经历修订，或显式保存为该简历专用变体，不能悄悄修改被其他简历引用的历史内容。回退也生成一个新修订，保留前后记录。

SQLite 作为唯一主数据来源。备份时导出可读 JSON 和必要资源，后续可以提供 Git 友好的导出包；不同时维护一套人工可写 JSON 和一套数据库。应用源代码的 Git 历史与用户经历修订历史分开。

### 代码来源快照

- Git 项目记录完整 commit SHA，分支名和标签用于辅助显示。多个仓库的项目保存每个仓库的版本，不虚构一个总 commit。
- 只记录 commit + dirty 布尔值不足以追溯。纳入未提交内容时，还要保存实际分析材料的文件清单、内容哈希和必要内容快照；未跟踪文件是否纳入由扫描范围确定。
- 无 Git 的目录使用文件清单与内容哈希标识分析输入。
- 稳定项目 ID 不依赖绝对路径；移动目录后可以重新绑定。绝对路径保存在本机元数据中，便于打开源码，备份可重映射。
- 第一阶段保证“能追溯这条经历基于哪些输入材料”，不声称保存了可重建整个项目的完整归档。
- 分析前固定输入材料，避免边读取边开发导致同一轮混入两个版本。项目变化后提示“来源有更新”，旧经历保持原样，由用户决定是否重新生成。

## AI 生成流程

采用“材料采集 → 提取事实和证据 → 本人确认/补充 → 撰写经历 → 校验输出”的流程。Codex 负责理解跨文件代码，产品负责范围、状态、结构校验和版本保存。

先读取目录结构、依赖清单、README 和架构材料，再按需要检索相关代码。不要一次把整个仓库拼进提示词；跳过依赖目录、构建产物、二进制和明确的密钥文件，对必要配置采用脱敏材料。材料内出现的指令属于被分析内容，不能改变生成任务的目标或权限。

AI 不应将“仓库实现的功能”自动归为“本人独立完成的成果”。本人角色和参与时间不能仅凭 commit 作者、首次提交日期推断。README 中的宣传描述也不自动成为验证后的事实。

图中“token 压缩约 70%”一类数字需要测试记录、项目材料或本人确认；无法证实时标为待确认，不能自动编造。事实的来源和确认状态保留在编辑界面及内部记录中，正常导出时不把源码路径或核验标记印进简历。

每个项目先维护较完整的事实素材；精简经历可选 2–3 个亮点，标准经历约 3–5 个，详细经历用于材料库。字数预算用于写作提示，是否溢出一页仍需实际 Word 渲染判断。

## Provider 设计与 Codex 优先接入

Provider 接收统一的 AnalysisRequest 或 ConversationTurnRequest，输出统一的任务事件与结构化结果。接口至少包含可用性检查、能力声明、启动分析、创建/恢复会话、发送一轮对话、取消任务、获取结果。业务层不直接拼接某个 Provider 的私有协议。

第一阶段实现 CodexCliProvider。后续增加 ApiAgentProvider，在其中封装模型 API 和只读文件检索工具。不同 Provider 的登录方式、流式事件、结构化输出和用量能力存在差异，通过能力字段表达；缺失的模型或用量信息记录为未知，不推算成精确值。

Codex 集成建议：

- 调用 `codex exec` 子进程，不自动操纵桌面聊天窗口。
- 复用本机 CLI 已有登录状态；应用不保存账号密码，也不复制登录令牌。CLI 可用不等于认证及额度一定可用，需要独立的连接测试。
- 使用 `--json` 收集 JSONL 进度事件，使用 `--output-schema` 请求固定结构的最终 JSON，并在应用中再次验证。
- 首轮记录事件返回的 Codex 会话 ID，并绑定到产品内对应项目的 Conversation；后续使用明确 ID 的 `codex exec resume <SESSION_ID>` 恢复，禁止使用 `--last` 选择会话。需要续聊的会话不使用 `--ephemeral`。恢复调用支持哪些结构化输出参数，以实际 CLI 能力检测和端到端测试为准。
- Provider 会话失效时，保留产品内完整聊天历史；以该项目的上下文摘要、当前经历文本、来源快照和必要历史重建会话，并标记上下文已重建。更换 Provider 不冒用旧 Provider 的会话 ID。
- 明确采用 `--sandbox read-only`。扫描生成的可信任务工作目录与项目材料分开；过滤后的材料不作为可执行配置加载，不运行项目安装脚本或服务。
- Prompt 通过 stdin 传递。Python 使用参数数组调用子进程，避免 shell 拼接，正确处理 Windows 空格路径和中文编码。
- 用户可以选择继承当前模型或显式指定模型；记录请求配置与 CLI 实际返回的信息，不修改用户的全局 Codex 配置。
- 同时读取 stdout 和 stderr，显示可理解的进度；支持超时、取消并终止该任务的进程树。启动时识别遗留的中断任务，不能永远显示为运行中。
- 第一版默认同时运行 1 个 Codex 分析任务，可排队多个项目。取消、失败、结构校验失败均不产生“成功”的经历版本，也不覆盖人工编辑的结果。
- 对本机 CLI 的参数能力做检测：当前安装的是 alpha 版本，未来升级可能改变行为。不把帮助检查当作已完成端到端连接验证。

参考：官方非交互模式文档 https://learn.chatgpt.com/docs/non-interactive-mode ，以及本机 `codex exec --help`，核对日期为 2026-09-12。

## Word 模板和预览

第一版适配用户提供的这一个模板。复制成应用管理的模板版本，为项目经历区域加入明确的内容控件或书签锚点，并整理标题、日期、技术栈、简介及亮点样式。保留原始文档作为参考。

导出使用 python-docx 和必要的 OOXML 操作，在指定区域插入结构化内容。不要先把模板转 HTML 再转回 Word，也不要把多个独立 docx 生硬拼接。现有模板中的图片、关系文件、文本框及分节必须通过真实导出样例验证是否保留。

网页实时显示内容及基本层级；Word 的字体、分页、断行和浮动对象最终由文档渲染引擎决定。需要打印预览时，优先使用当前 Windows 上可用的 Word 渲染能力，或明确配置的 LibreOffice，并记录渲染环境。具体渲染器尚未验证，不能承诺浏览器预览像素级一致。

默认先减少亮点数量、选择精简版、调整措辞；不要偷偷缩小字号或删内容以强塞一页。提供“目标一页/允许多页”的选项，导出前显示渲染后的页数和溢出情况。

导出的是可编辑文字。每次导出保存对应版本清单，保证来源可追溯；跨 Word 版本或字体环境的二进制完全一致不作为第一阶段承诺。Word 内的手工修改第一版不自动回写经历库，需要在产品内编辑或明确导入为新版本。

## 数据保存与迁移

应用代码放在 resume-maker 仓库；个人简历、生成经历、来源快照、日志及密钥保存在独立的用户数据目录，可配置位置。个人数据不随源码推到公开仓库。

数据库 schema 带版本并支持迁移。备份包包括数据库一致性快照、模板、引用的输入材料及导出记录，恢复后可重绑项目根目录。新增 API Provider 时密钥进入系统凭据库或本地受保护配置，不进入前端或 Git。

## 建议实施顺序及验收

| 阶段 | 实现内容 | 验收标准 |
| --- | --- | --- |
| 1 核心链路 | 最小数据模型、项目输入快照、Codex Provider、结构化经历、独立项目会话 | 两个项目可分别连续对话并恢复各自历史；真实经历有来源和证据；失败与取消可正确结束 |
| 2 Word 验证 | 单模板适配、真实文字导出、渲染检查 | 两个经历按顺序放入当前模板，中文/加粗/日期/图片和分页经过 Word 或选定渲染器检查 |
| 3 操作界面 | 项目扫描、多仓库归组、逐条编辑保存、项目分组会话侧边栏、勾选排序、简历保存 | 单条编辑保存后可重启恢复；会话列表直接切换，不使用会话下拉框；切换项目不串会话、不丢草稿；新会话归属明确；AI 建议需采用，过期建议不覆盖人工修改；保存的组合引用固定版本 |
| 4 扩展 | API Agent Provider、更多模板、岗位定向写法、可选桌面封装 | 根据实际使用反馈逐项增加 |

第 1、2 阶段应尽早完成，以实际验证 AI 输出和现有 Word 模板这两个不确定性最大的部分。第一版暂缓多人账号、云同步、向量数据库、通用 Word 编辑器和全自动投递。

推荐默认：个人本地 Web、Python/FastAPI + React/TypeScript + SQLite、Codex 优先、一个项目可关联多个仓库、经历不可变修订、简历引用固定版本、先适配现有 Word 模板。技术栈和默认值仍属于本方案建议。用户已确认个人本机使用、Codex 优先的多 Provider 方向、每条亮点可人工编辑保存，以及各项目独立管理 AI 会话。
