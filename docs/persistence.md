# 数据持久化

用户输入分为自动保存的编辑草稿和显式保存的正式资料。自动保存不会提交经历版本、改变简历固定引用、确认荣誉或登记模板。

| 数据 | 保存位置 | 恢复方式 |
| --- | --- | --- |
| 项目、经历、分支、引用证据、会话及项目 AI 任务 | 现有 SQLite 表，证据文件放在 `snapshots/` | 重启后读取，运行中的项目 AI 任务标记中断 |
| 简历资料、照片、栏目、组合及模板选择草稿 | `settings` 中的 `workspace-value:rm.*` | 首屏挂载前加载，可跨浏览器及备份恢复 |
| 荣誉人工核对、本人贡献、来源输入、默认栏目、模型和隐私设置草稿 | 同一独立草稿存储 | 再次打开对应表单恢复，保留正式资料版本以检查冲突 |
| 模板人工映射、名称和反馈 | 按分析标识保存的独立草稿 | 选择“继续模板工作”恢复 |
| 模板任务、进度及建议 | `settings` 中的 `template-task:<id>` | 完成任务直接恢复；在途任务标记中断，用户显式重试 |
| 模板分析原件和可编辑文档 | `template-drafts/<id>/` | 随任务备份，原导入文件移动或删除后仍可核对和重试 |
| 已保存模板、荣誉附件和导出成品 | `templates/`、`honors/`、`exports/` | 随数据库备份恢复 |
| 主题、布局、排序、日志显示规则和当前选择 | 独立草稿存储中的偏好键 | 随资料恢复，多个窗口采用最后一次选择 |
| 系统日志 | `logs/activity.sqlite` | 本机重启保留，不进入资料 ZIP，可单独导出 |

搜索词、选区、加载状态、排版缓存、脱敏还原表和 CLI 临时文件不属于长期资料。预览可重新生成，敏感词检测框中的临时原文不额外持久化。原项目源码及外部 CLI 登录配置不进入备份。

## 自动保存和冲突

共享存储先记录本窗口的浏览器恢复副本，再在连续输入停止后写入本机数据库。网络中断或磁盘错误会显示保存失败，并保留输入供重试；仍有未确认写入时，关闭页面会触发浏览器提示。浏览器禁止存储或空间不足时，会提示等待数据库保存完成。

右下角在保存期间显示状态，保存成功后显示两秒再自动隐藏；初始空闲状态不显示提示。保存失败、版本冲突及恢复副本入口持续保留，直到相关问题得到处理。

每个内容草稿使用独立版本号，删除也保留版本。两个窗口编辑同一份内容时，旧版本不能覆盖新版本。可以选择保留本页修改或载入已保存内容，冲突中另一份内容保留为恢复副本。界面偏好采用最后一次选择，不阻止不同窗口编辑各自简历。

经历及会话先完成各自草稿接口写入，再刷新共享草稿层，导航和备份共用此顺序。正式资料保存失败时仍保留草稿。明确取消荣誉核对或默认栏目设置会放弃对应表单草稿，刷新和异常退出保留草稿。

首次升级会将原有 `rm.resume.v2.*`、经历、会话及本人贡献的浏览器缓存导入当前数据目录，并保留原缓存。浏览器导入归属绑定当前数据目录；切换数据目录或恢复旧备份后，不会把另一份资料的旧缓存自动写入。

## 备份一致性

备份先取得数据库写事务，再通过独立读连接创建 SQLite 快照，并复制快照中登记的附件。期间附件删除和业务提交等待写锁释放。只收录登记的资源，不打包工作目录中的 CLI 配置、临时材料、日志或可重建缩略图。

ZIP 先写临时文件，全部完成后才发布。版本 2 备份包含每个文件的大小及 SHA-256；恢复时先在隔离目录核验 ZIP 路径、文件清单、校验和、数据库结构、外键和必需附件，再保留旧目录并切换。现有版本 1 备份仍可通过原有结构校验恢复。

`template-cache/` 是合法应用缓存目录，允许原地恢复。恢复会轮换浏览器草稿代次，防止尚未同步的旧浏览器输入覆盖用户选择恢复的备份；旧浏览器恢复副本不会被删除。

数据库为 v8；v6/v7 升级前保留原库，再迁移目录册及稳定引用。新库由清单按所选模块建表，既有资料继续保留。内置表、引用规则及目录册同事务初始化，失败全部回滚。

## 插件数据及配置

`plugins.json` 保存所选组合、配置、代次和包摘要。`plugin-operations/` 保存逐项操作状态；它属于本机维护记录。备份保存组合意图和插件资料，不携带可执行包、解释器环境、系统日志或凭据。

资源目录册独立于活动插件：停用、卸载或恢复时缺包，都不使模板原件、荣誉附件、已发布 assets 及 `plugin-data/<插件ID>/` 消失。外部表和 settings 必须使用插件命名空间；版本不兼容拒绝写入。历史附件目录归属在升级后继续保留。

新增外部私有表从版本 0 开始，以包内 JSON 迁移文件经停机维护建立。迁移计划锁定原数据库、插件和文件摘要，先生成完整 ZIP，再于数据库副本转换；检查完整性和外键后替换，失败不发布副本。包回退不自动回退数据，恢复旧资料必须使用相应备份。

正式导出及临时预览固定输入快照，成品记录插件、提供方、配置代次和输入摘要。经历修订及历史成品保持不可变。任务调度意图和领域输入在同一数据库事务保存。`task-execution:*` 是实际执行租约记录，业务任务状态仍归领域所有者；重启将未完成执行标为中断，不自动重放模型请求。

浏览器恢复副本另带插件代次。切换前所有已登记窗口须确认保存；离线窗口只有用户明确选择保留恢复副本后才可继续，超时不能当作同意。未知简历 extensions 原样保留，导出需要可显示的纯文本快照或明确隐藏标志。

旧窗口返回后可点击“重新协商并加载”。命令和草稿处理全部收尾后，如果保存失败，界面会核对服务器是否已换代；确认换代且宿主就绪后，先确保未保存输入进入浏览器恢复副本再刷新。新窗口仅展示旧代次副本，不自动重放。副本无法保存、代次未变或当前状态无法确认时，保留原页面供处理和重试。


可选插件资料版本不兼容时，启动会保留其期望选择和资料，只阻断该插件及依赖消费者；最小系统继续可用。系统插件资料不兼容仍拒绝启动。

资源回收通过停机计划处理超过 24 小时的失败暂存、墓碑及无登记目录。解除引用必须与业务删除共用事务；墓碑标记要求无引用、无租约。应用计划时核对资料目录、摘要、记录及实际文件，所有候选复核成功后才回收，并持有备份共用写锁。意外中断留下的待维护记录可重新生成计划处理，已发布资料不自动回收。命令见 [插件开发协议](plugin-sdk.md)。

统一资源迁移把旧模板、证书、来源证据和成品发布到 assets，保存原件清单和每份摘要。中断后继续同一迁移记录，核验成功才删除旧副本。新导出只保留 assets 中的一份持久文件，HTTP 下载持有传输租约。

整组插件升级在独立资料副本完成所有迁移后才替换正式库。`host-transition.json`、`plugin-migrations/`、`plugin-trials/`、下载记录和版本锁属于本机维护状态，不进入资料备份。显式原地恢复允许这些目录，并完整保留故障现场；恢复后的新目录不重放旧升级、不加载备份代码、不初始化未选择模块的表。详见 [当前插件协议](plugin-sdk.md)。
