# 数据持久化

用户输入分为自动保存的编辑草稿和显式保存的正式资料。自动保存不会提交经历版本、改变简历固定引用、确认荣誉或登记模板。

| 数据 | 保存位置 | 恢复方式 |
| --- | --- | --- |
| 项目、经历、分支、引用证据、会话及项目 AI 任务 | 现有 SQLite 表，证据文件放在 `snapshots/` | 重启后读取，运行中的项目 AI 任务标记中断 |
| 简历资料、照片、栏目、组合及模板选择草稿 | `settings` 中的 `workspace-value:rm.*` | 首屏挂载前加载，可跨浏览器及备份恢复 |
| 荣誉人工核对、本人贡献、来源输入、默认栏目、模型和隐私设置草稿 | 同一独立草稿存储 | 再次打开对应表单恢复，保留正式资料版本以检查冲突 |
| 模板人工映射、名称和反馈 | 按分析标识保存的独立草稿 | 选择“继续模板工作”恢复 |
| 模板任务、进度及建议 | `settings` 中的 `template-task:<id>` | 完成任务直接恢复；在途任务标记中断，用户显式重试 |
| 模板分析原件和可编辑文档 | `template-drafts/<id>/` | 随任务备份，原导入文件移动或删除后仍可核对和重试 |
| 已保存模板、荣誉附件和导出成品 | `templates/`、`honors/`、`exports/` | 随数据库备份恢复 |
| 主题、布局、排序、日志显示规则和当前选择 | 独立草稿存储中的偏好键 | 随资料恢复，多个窗口采用最后一次选择 |
| 系统日志 | `logs/activity.sqlite` | 本机重启保留，不进入资料 ZIP，可单独导出 |

搜索词、选区、加载状态、排版缓存、脱敏还原表和 CLI 临时文件不属于长期资料。预览可重新生成，敏感词检测框中的临时原文不额外持久化。原项目源码及外部 CLI 登录配置不进入备份。

## 自动保存和冲突

共享存储先记录本窗口的浏览器恢复副本，再在连续输入停止后写入本机数据库。网络中断或磁盘错误会显示保存失败，并保留输入供重试；仍有未确认写入时，关闭页面会触发浏览器提示。浏览器禁止存储或空间不足时，会提示等待数据库保存完成。

每个内容草稿使用独立版本号，删除也保留版本。两个窗口编辑同一份内容时，旧版本不能覆盖新版本。可以选择保留本页修改或载入已保存内容，冲突中另一份内容保留为恢复副本。界面偏好采用最后一次选择，不阻止不同窗口编辑各自简历。

经历及会话先完成各自草稿接口写入，再刷新共享草稿层，导航和备份共用此顺序。正式资料保存失败时仍保留草稿。明确取消荣誉核对或默认栏目设置会放弃对应表单草稿，刷新和异常退出保留草稿。

首次升级会将原有 `rm.resume.v2.*`、经历、会话及本人贡献的浏览器缓存导入当前数据目录，并保留原缓存。浏览器导入归属绑定当前数据目录；切换数据目录或恢复旧备份后，不会把另一份资料的旧缓存自动写入。

## 备份一致性

备份先取得数据库写事务，再通过独立读连接创建 SQLite 快照，并复制快照中登记的附件。期间附件删除和业务提交等待写锁释放。只收录登记的资源，不打包工作目录中的 CLI 配置、临时材料、日志或可重建缩略图。

ZIP 先写临时文件，全部完成后才发布。版本 2 备份包含每个文件的大小及 SHA-256；恢复时先在隔离目录核验 ZIP 路径、文件清单、校验和、数据库结构、外键和必需附件，再保留旧目录并切换。现有版本 1 备份仍可通过原有结构校验恢复。

`template-cache/` 是合法应用缓存目录，允许原地恢复。恢复会轮换浏览器草稿代次，防止尚未同步的旧浏览器输入覆盖用户选择恢复的备份；旧浏览器恢复副本不会被删除。

本次沿用 `settings` 扩展存储，不变更业务数据库结构版本，也不自动清空既有资料。
