# 编号脱敏修复（2026-09-21）

本地证书审计发现两组 15 位编号仅被其中命中的短敏感词局部遮盖。旧规则未覆盖完整编号，导致其余数字仍保留在交给 CLI 的材料中；纯数字提示还可能因为被解析成 JSON 数字而绕过文字规则。替换次数无法证明完整性。

修复增加完整编号范围识别，覆盖连续 12 位及以上数字、常见数字分组、明确的准考证号及报告单等标签、结构化编号别名和分组校验串。NFKC 归一化后的匹配映射回原文，保留原始字符及换行；OCR 正文发现的分块也参与脱敏。重叠命中范围合并为完整遮盖，短数字敏感词受边界约束，本轮占位符重复处理保持稳定。

合成回归在修改前复现 20 项失败，修复后扩充为 22 项，验证 13、15、18 及更长编号，全角、控制符、空格、连字符、斜线、CRLF 和 LF，带标签的短编号和字母数字校验串，重叠敏感值及 OCR 分块。对照用例保留成绩、日期、年份列表、坐标和源码变量；真实隐私 Provider 的合成输出能够准确还原编号。原生 CLI 对本机假 Responses 服务额外验证大文件引用中的编号完整遮盖及本机还原。

实际上传证书只在本机复核，供应商调用被本地替身完全替代。复核确认四组长数字及分组校验串完整遮盖，成绩和考试日期保留，原件哈希不变，原始审计未改写。真实材料、映射和复核输出均位于忽略目录，不进入测试或提交。

完整检查通过：720 项后端测试、125 项前端测试、中文说明及依赖检查、Ruff、前端类型及格式检查、生产构建。后端显式启用真实 Windows CLI 对本机模拟服务的验收，覆盖普通模型、GPT-5.5、GPT-6-Astra；无真实供应商请求。wheel 构建及仓库外安装包检查通过，本地 OCR、静态资源、源码材料工具和脱敏还原可用。

此修复不会撤回过去已发送的内容；自动规则仍不能识别全部未知姓名、无标签短编号或任意编码。详细边界见[隐私保护](privacy.md)。
