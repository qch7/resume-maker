> 版本：讨论稿 v0.2
>
> 文档更新日期：2026-09-27；链接检查日期：2026-09-26
>
> 范围：中国互联网企业为主，首批整理 30 家企业／招聘主体，另附 6 家科技企业。
>
> 2026-10-03 实现更新：已实现自定义招聘收藏夹和 JSON 导入导出。初始无领域、分类或网址；大厂、中厂、小厂仅随示例文件导入，分类可增删改名。以下企业清单作为可下载的导入示例提供。当前功能以 [招聘收藏夹说明](recruitment-bookmarks.md) 为准；本文其余内容保留为资料和讨论草案，后续设想不代表已实现。招聘批次、岗位和截止时间以企业当期页面为准。

## 1. 建议做成什么

在 Resume Maker 中增加独立的 **“招聘导航”**：预装互联网领域的企业和招聘入口，按**大厂、中厂、小厂**分类，支持自行添加领域、企业及网站，逐步积累成自己的求职网址库。

第一版的使用路径：

1. 选择“互联网”，按“大厂、中厂、小厂”筛选企业，也可通过业务标签进一步筛选。
2. 查看企业简介、招聘主站、校招入口和其他已收录链接。
3. 打开官网、收藏企业、记录自己的关注点。
4. 需要扩展时，新增“金融”“半导体”“新能源”等领域，再录入相应企业和官网。

后续再把感兴趣的岗位、准备投递的简历方案和投递进度连接起来。

## 2. 分类方式：大厂、中厂、小厂

### 2.1 固定三类，支持调整企业归类

企业分类固定为**大厂、中厂、小厂**，默认按这个顺序展示。每家企业只选一类，用户可以直接调整归类；新增企业时也需选择一类。

| 分类 | 初始归类口径 | 当前互联网预设 |
| --- | --- | --- |
| 大厂 | 业务体量较大、覆盖范围较广，或在所属赛道具有较强规模和求职知名度的企业 | 20 家，例如腾讯、阿里巴巴、字节跳动、网易、米哈游 |
| 中厂 | 已形成稳定业务和团队，整体体量或业务覆盖相对集中的企业 | 10 家，例如得物、知乎、莉莉丝、叠纸、鹰角 |
| 小厂 | 规模较小的公司、创业团队、独立工作室等 | 暂不预置，支持用户自行添加 |

这是一套便于求职导航的初始归类，综合考虑体量、业务覆盖和常见求职认知；边界企业可按个人习惯调整。当前清单主要来自大中型企业，小厂栏目保留为空，不将资料不足的企业自动归入小厂。

### 2.2 领域和业务方向分别保存

导航结构为：**领域 → 大厂／中厂／小厂 → 企业 → 官网和招聘入口**。

| 信息 | 用途 | 示例 |
| --- | --- | --- |
| 领域 | 选择关注的行业，可自行添加 | 互联网、金融、半导体、新能源 |
| 企业分类 | 固定三类，每家企业单选 | 大厂、中厂、小厂 |
| 业务标签 | 补充业务方向，允许多选和自定义 | 电商、游戏、云计算、社交、网络安全 |

默认领域为“互联网”，另提供“科技硬件和企业服务”可选预设。腾讯可标注“社交、游戏、云”，网易可标注“游戏、内容、教育”。业务方向用于标签筛选，页面主分组统一使用大厂、中厂、小厂。

## 3. 首批招聘入口清单

### 阅读说明

- **A · 浏览器复核**：已在浏览器看到主入口的招聘页面和导航。
- **B · 页面初检**：主入口返回成功页面，并识别到对应招聘标题或内容；未完整操作动态页面。
- **C · 待复核**：已找到候选入口，但本次未能完成页面核验。
- 状态针对每行的**主入口**。补充入口来自本次页面导航、官方跳转或页面标题检查，单独受限的链接会注明。
- “进入站内选择”表示目前仅收录统一入口，不代表已逐一核验所有招聘类型。网站可访问也不等于当前一定有适合的岗位。
- 保留长期招聘入口；不把某一年的活动页、内推码或临时岗位 ID 当作企业唯一入口。

### 3.5 集团、品牌和入口的处理说明

阿里的入口应按“集团 → 招聘业务入口”组织。本次集团导航中能看到淘天、淘宝闪购、飞猪、阿里国际、阿里云、高德、菜鸟等入口。页面也明确说明招聘网站的展示不代表集团业务组织架构，因此应用只记录招聘导航关系，不据此推断法律主体或汇报关系。

微信、抖音、淘宝等名称可以作为品牌关键词指向企业；具有独立招聘站的业务再增加子条目，避免把同一个入口重复登记成多家公司。子条目默认沿用所属企业的分类，独立维护时允许调整。

滴滴首页将 `careers.didiglobal.com` 标为**海外招聘**。国内岗位导航优先使用 `talent.didiglobal.com`，不能因为前者本次连接失败，就把它认定为废弃网址。

腾讯游戏等已包含在集团条目中，可以通过游戏标签一起筛出，不重复计算企业数量。

## 4. 每条信息建议存哪些字段

### 4.1 企业／机构条目

| 字段 | 用途 | 首版建议 |
| --- | --- | --- |
| 名称、简称、别名 | 搜索“B 站”也能找到哔哩哔哩 | 名称必填，其余可选 |
| 所属领域 | 互联网、金融、半导体等，允许多选 | 必填，支持自建领域 |
| 企业分类 | 大厂、中厂、小厂 | 必填、单选，可调整企业归类 |
| 业务标签 | 游戏、云、电商、网络安全等 | 多选，可自定义 |
| 简介 | 一两句话说明主要业务 | 可选 |
| 招聘关联关系 | 集团、业务品牌、独立招聘入口之间的关系 | 可选，不强制等同于股权关系 |
| 网站列表 | 同一企业可有多个官网和招聘入口 | 至少一个链接 |
| 收藏、置顶、隐藏、排序 | 管理个人关注名单 | 首版支持 |
| 个人备注 | 关注原因、岗位方向、投递优先级 | 本机保存 |
| 来源和核验记录 | 区分预设／自建、出处、检查时间和方式 | 首版支持 |

### 4.2 每个网站链接独立记录

| 字段 | 示例／规则 |
| --- | --- |
| 链接名称 | 腾讯招聘、腾讯校招、集团招聘导航 |
| 链接类型 | 企业官网、招聘门户、校招、社招、实习、海外招聘、技术社区、其他；允许自定义类型 |
| URL | 优先保留企业长期入口；必填 |
| 适用范围 | 业务、国家／地区、语言；有明确依据再填写 |
| 来源页面 | 从哪个企业官网或招聘公告发现该链接 |
| 承载方式 | 企业域名、官方使用的招聘服务平台、第三方信息站、待确认 |
| 检查状态和日期 | 浏览器复核、页面初检、待复核、访问受限、已确认停用 |
| 目标地址和备注 | 记录 Moka、飞书等跳转目标及用途，保留稳定来源入口 |

城市、岗位方向、学历要求、薪资、招聘年份、截止时间属于变化较快的信息。后续若收录，应记录来源、适用岗位／批次和更新时间；企业总部城市不能直接当成招聘城市。

“有校招入口”“某一批校招正在进行”“某岗位仍可投递”应分开记录。首版提供入口信息，不从链接存在推断招聘状态。

| 顶部 | 搜索框、添加企业、添加领域、管理标签 |
| 筛选区 | 领域、大厂／中厂／小厂、业务标签、链接类型、收藏、核验状态 |
| 企业列表 | 按大厂、中厂、小厂分组，展示名称、简介、标签、招聘按钮、校招按钮、收藏和更多操作 |
| 企业详情 | 全部链接、来源、最近检查时间、个人备注、编辑入口 |

默认显示互联网领域的全部三类企业；空分类显示“暂无企业”和添加入口。搜索同时匹配企业名、简称、品牌关键词和备注。切换分类或领域时保留搜索条件，用户可一键清空筛选。

官方网站在浏览器新标签页打开。官网要求登录、填写和提交的动作在官网完成；单纯打开链接不记为“已投递”。

### 5.2 自己添加领域和官网

例如新增“金融”领域：

1. 新建领域“金融”，按需要增加“银行”“证券”“保险”等业务标签。
2. 添加企业，填写名称、简介，从“大厂、中厂、小厂”中选择一类，再选择业务标签。
3. 添加企业官网、校园招聘、社会招聘等多个链接，也可只填一个统一招聘入口。
4. 保存后立即参与搜索、收藏和排序；用户手动录入的链接默认显示“用户添加／未核验”。

领域和标签用稳定 ID 保存，改名不丢失企业关系。删除仍被使用的领域时，先迁移企业或移除该领域关联，确保每家企业至少保留一个领域。大厂、中厂、小厂作为固定分类保留，企业可在三类之间移动。

对于暂时没有招聘入口的企业，也允许先保存企业官网并备注，之后补齐信息。

### 5.3 预设和个人修改如何共存

- 内置清单只负责提供初始资料，每个预设企业和链接都有稳定 ID。
- 用户可以编辑预设、增加自己的链接、调整分类、收藏、隐藏条目。
- 更新预设时展示新增、变更和停用建议，保留个人备注、排序、收藏及已修改字段。
- 用户主动隐藏的条目不因预设更新再次出现；删除和恢复行为应可预期。
- 复制条目时生成新的用户条目；相同企业主入口提供重复提示，允许保留不同业务或地区的入口。
- 导入时先展示冲突处理结果，再合并或保留副本，避免整库覆盖。

## 6. 分阶段整合建议

### 第一期：可用的招聘网址库

建议首版包含：

- 本文 30 家互联网及软件企业的预设，C 状态条目标明待核验；6 家科技企业可按领域选用。
- 固定大厂、中厂、小厂三类，支持调整企业归类和类内排序。
- 自定义领域、业务标签、企业和链接类型，支持增删改。
- 搜索、筛选、收藏、置顶、隐藏和个人备注。
- 一个企业多个入口，显示来源和核验状态，点击打开官网。
- 本机持久化、页面输入草稿、版本冲突保护，纳入现有 ZIP 备份和恢复。

第一期按用户维护的网址目录实现。岗位批次、截止时间和投递记录另行设计，避免把网站通断误当成招聘变化。

### 第二期：连接岗位和简历

- 手动保存岗位名称、原始链接、JD、城市、招聘批次和截止时间。
- 为岗位关联已有简历方案；真正投递时关联具体导出成品，保留投递时的版本。
- 手动记录“关注、准备、已投递、笔试、面试、Offer、结束”等状态。
- 用户选择某份 JD 和简历后，再使用现有 AI 出口做匹配分析和修改建议，继续经过现有隐私网关。

### 第三期：可选维护能力

- 导入／导出自定义清单，优先 JSON；表格格式可按需要增加。
- 用户主动执行链接检查，区分正常、重定向、登录限制、验证页面、超时和明确失效。
- 按企业逐步增加官方公告整理、校招批次记录等能力，并显示原始出处。

## 7. 结合现有项目的落地位置

当前 Resume Maker 使用 React、FastAPI 和 SQLite，已有独立功能区、本机草稿、收藏分类、备份和统一 AI 隐私出口，可沿用现有模式。

| 层次 | 建议 |
| --- | --- |
| 前端 | 新增 `features/recruitment`，由 `app` 接入导航，复用现有表单、搜索、收藏和草稿交互 |
| API／服务 | 使用 `recruitment` 命名，例如 `/api/recruitment/companies`；现有 `jobs` 已表示后台任务，避免混用 |
| 数据 | 领域、企业、链接分别保存；企业分类使用大厂／中厂／小厂固定字段，多领域和多标签使用关联关系，收藏备注留在本机用户数据中 |
| 预设 | 以版本化结构化资源随应用分发，安装包也包含资源；本地修改和预设来源分开记录 |
| 持久化 | 写入现有业务 SQLite，采用事务和版本校验；自定义资料纳入现有备份，不只依赖浏览器存储 |

第一版无需引入爬虫、第三方搜索服务或新的 AI 调用。导航结构可归纳为：**领域 → 大厂／中厂／小厂 → 企业条目 → 多个网站链接**，业务标签跨企业复用。

## 8. 本次核验范围和需要保留的来源

本次检查了表中招聘主入口和所列补充链接，通过页面标题、公开页面导航及重定向确认用途；关键动态页面另用浏览器复核。没有登录招聘账户，也没有提交简历。A、B 状态均不代表已测试账号、申请表或完整投递流程。

几个会影响预设设计的实际例子：

| 来源 | 本次观察 | 对清单的影响 |
| --- | --- | --- |
| [阿里集团招聘](https://talent.alibaba.com/) | 集团导航按业务分流，并提供校园招聘链接 | 支持一个集团多个招聘入口 |
| [PDD 校招](https://careers.pddglobalhr.com/campus/) | 页面区分应届生招聘和实习生招聘 | 明确入口类型，社招另补 |
| [滴滴招聘](https://talent.didiglobal.com/) | 国内社招、校招、海外招聘分别导航 | 保存地区和用途，不混为同一入口 |
| [唯品会“走进唯品”](https://h5rsc.vip.com/h5rscSupportContactV/h5rscSupportContactV/index.html) | 官方页面指向 `job.vip.com`，再跳到 Moka | 保存官方来源和跳转关系 |
| [去哪儿官网](https://www.qunar.com/) | “加入我们”指向 `zhaopin.qunar.com`，再跳到飞书招聘 | 企业使用第三方招聘平台仍可作为官方渠道 |
| [知乎招聘入口](https://www.zhihu.com/careers) | 官方 URL 跳转到 Moka 的知乎招聘页 | 官方入口优先于搜索到的活动链接 |
| [大疆招聘](https://careers.dji.com/zh-CN/) | `we.dji.com` 重定向至新域名路径 | 允许更新首选网址并保留旧入口记录 |
| 同程旅行招聘和校招入口 | 搜索可找到企业域名页面，但本次连接超时 | 保留 C 状态，后续复核，暂不标记已停用 |

核验状态按链接维护，不能因为一个入口超时就删除整家企业。Moka、飞书等平台链接应由企业官网跳转或官方公告证明来源，普通搜索结果只用来发现候选。

建议先按本文的分类、企业范围和“自定义领域＋多个官网入口”完成第一版；个人投递管理作为后续扩展。
